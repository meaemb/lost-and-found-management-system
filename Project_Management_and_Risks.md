# 10. Project Management and Risks

## 10.1. Introduction

Project management activities for the Multi-Organization Lost and Found Management System are organized to ensure clear responsibility allocation, traceability of project deliverables, and systematic identification of potential risks.

The project is developed by a team of two students. GitHub is used for version control and documentation management, while YouTrack is used for task planning, assignment, progress monitoring, and tracking of deliverables.

At the first pre-defense stage, the main focus is on requirements analysis, research, technology selection, system architecture, interface prototyping, and planning for subsequent implementation and evaluation.

## 10.5. Project Dependencies

Several project activities depend on the completion of earlier deliverables.

| Activity | Main Dependency | Explanation |
|---|---|---|
| Requirements specification | User research and existing systems analysis | Requirements must reflect identified user needs and system limitations |
| System architecture | Requirements and technology selection | Architecture must support the required functions and selected technologies |
| User interface design | Functional requirements and user roles | Interfaces must reflect the intended workflows and permissions |
| Database and backend implementation | Architecture and data model | Implementation requires defined entities, relationships and responsibilities |
| Automated matching | Item reporting and data storage | Matching requires structured lost and found records |
| Ownership verification | Matching and claim management | Claims must be associated with relevant found items |
| Return process tracking | Ownership verification workflow | Item return follows an approved ownership claim |
| System evaluation | Implemented functionality | Testing requires executable workflows and representative test data |

These dependencies help determine implementation priorities and reduce the risk of developing features before their prerequisites are established.

## 10.6. Risk Management

The team identified preliminary risks that may affect the successful completion of the project.

| Risk | Probability | Impact | Mitigation Strategy |
|---|---|---|---|
| Limited development time | High | High | Prioritize core functionality and implement features incrementally |
| Complexity of multi-organization access control | Medium | High | Define organization-aware authorization rules and test restricted access |
| Inaccurate automated matching | Medium | High | Start with transparent rule-based scoring and evaluate matching on representative records |
| Unauthorized access to ownership evidence | Medium | High | Restrict sensitive information, validate permissions and perform security testing |
| Insufficient user feedback | Medium | Medium | Conduct additional interviews and usability evaluations during development |
| Integration difficulties | Medium | Medium | Define API contracts and integrate frontend and backend functionality incrementally |
| Incomplete documentation or task traceability | Medium | Medium | Maintain updated YouTrack tasks, meaningful commits and linked pull requests |
| Delays in supervisor feedback | Medium | Medium | Request feedback in advance, document pending reviews and incorporate comments when received |

Risk management will be revisited during implementation. The team will review risk probability, potential impact, and mitigation effectiveness as project activities progress.

## 10.7. Progress Tracking and Traceability

Project activities are tracked through the YouTrack board and the GitHub repository.

Each major deliverable is associated with a YouTrack task containing its description, expected outcome, acceptance criteria, responsible team member, and deadline.

Where applicable, tasks also include links to related GitHub pull requests. This connection provides traceability between planned work and submitted deliverables.

The repository contains project documentation and design materials. Git history and pull requests provide additional evidence of individual contributions and changes.

At the first pre-defense stage, the documentation and design deliverables form the foundation for subsequent software implementation.

## 10.9. Conclusion

The project management approach combines structured task planning, version control, responsibility allocation, milestone tracking, and risk management.

The identified risks and mitigation strategies will guide development decisions and help the team monitor project progress throughout the remaining stages.
